Watch Docker events live

Updated 28 November 2026

docker events prints a raw stream that is gone once it scrolls past. The Events tab in dpad keeps a timeline you can filter and scroll, with Compose project and service names on every row.

Open the timeline

In dp, press 5. Recording starts when dp opens, so the tab fills as things happen.

It records container lifecycle and health events: create, start, stop, restart, die, destroy, pause and unpause, rename, update, kill, OOM and health changes. Each row has the local time, the container, its Compose project and service, and the exit code, signal or image when Docker sends one. Noisy exec events are left out.

Find what happened

KeyAction
/Filter by container name or ID, project, service, event type or image (any case)
rReverse the order
gBack to the newest event, and follow new ones
d or enterOpen the container's details

Some useful filters:

  • shop: everything in the shop project.
  • die: containers that exited, with their exit codes.
  • oom: containers killed for running out of memory.
  • health: health checks changing state.

When you move through the list, the selected event stays put while new ones arrive above it.

Limits

This is a session timeline, not an audit log. It keeps the latest 1,000 events in memory and starts empty each time dp opens. If the connection to the daemon drops, a stream gap row marks where events may be missing, since Docker doesn't replay them. Destroyed containers keep their events, but their details are gone.
