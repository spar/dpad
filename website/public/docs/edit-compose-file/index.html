Edit a Compose file, locally or over SSH

Updated 28 November 2026

Bumping an image tag usually means finding the project's folder, opening the file, and hoping the YAML is right. In dpad, press e on the project. dpad finds the file, checks your change with Compose, and shows what it changes before anything is saved.

Edit, check, save

  1. In dp, press 4 for Projects and select a project row. (On a container row, e opens a shell instead.)
  2. Press e. If the project uses several Compose files, pick one.
  3. Edit the copy that opens, then save it (ctrl+s in the built-in editor, or quit your own editor).
  4. dpad runs docker compose config with your copy in place of the original, plus the project's other files and env files.

If Compose rejects the edit, you see its error, and e reopens the editor with your changes kept. If the edit is valid, dpad shows what it changes in the running project, such as web: nginx:1.27 → nginx:1.28 or services added and removed, and a diff of the file. Then:

KeyAction
enterSave, then open the update preview for the project
sOnly save
eEdit again
esc twiceDiscard the edit

The original file isn't touched until you save. Saving writes a temporary file beside it and renames it over the original, keeping its permissions, so a failed write leaves the original as it was. If the file changed on disk while you were editing, dpad refuses to overwrite it. No backup is kept, so keep your Compose files in version control.

The built-in editor

You don't need an editor installed. The built-in one colors the YAML, checks it as you type and marks the line the YAML parser rejects. It has no modes:

KeyAction
ctrl+f, then ctrl+n / ctrl+pFind, next, previous
ctrl+gGo to a line ($ is the last)
tab / shift+tabIndent or outdent by 2 spaces
ctrl+kDelete the line
ctrl+z / ctrl+yUndo / redo
ctrl+sSave the copy and check it
escClose (twice with unsaved changes)

Use your own editor

Press o for settings and enter on Editor. The picker lists the built-in editor and the editors it finds on your PATH: nano, vim, Neovim, vi, Emacs, micro, Helix, VS Code, Cursor, Zed, Sublime Text and Notepad. Your choice is saved as editor: in config.yaml; any other command works there too, for example editor: code --wait.

Without an editor: setting, dpad uses $VISUAL, then $EDITOR, then the built-in editor. Editors that open a window need their wait flag, which the picker adds for you.

Files on a remote host

When dp is connected to an ssh:// daemon and the project's files are on that server, editing works the same way over the same SSH connection. dpad reads the file with cat, you edit it locally, the check runs Compose on the server with your copy beside the original, and saving renames a temporary file over it there. The title says SSH host when this happens.

It needs key or agent SSH authentication, sha256sum or shasum on the server, and write access to the file's folder for your SSH user. dpad never uses sudo. Daemons reached over tcp:// or TLS give no way to reach files, so their projects can only be edited when the files are on your machine.
