docker stats can't sort, and it shows network and disk I/O as totals since each container started. dp stats keeps the same idea and fixes both, and the Stats tab in the TUI adds history and Compose grouping.

From the shell

$dp stats --sort mem
$ dp stats                   # live, sorted by CPU
$ dp stats --sort net -r     # network throughput, smallest first
$ dp stats --totals          # cumulative bytes instead of rates
$ dp stats --no-stream       # one snapshot, then exit

Sort keys are cpu, mem, net, io, pids and name. Numbers sort biggest first and names A to Z; -r reverses. While it runs, press c, m, n, i, p or a to sort by cpu, mem, net, io, pids or name, r to reverse, and t to switch between rates and totals. Snapshots and piped output always show totals, because a rate needs two samples. dp stats web db with container names goes straight to docker stats, since Docker already handles picking containers.

The Stats tab

Open dp and press 3.

KeyAction
s / rNext sort key / reverse
tRates or cumulative totals
vCompose projects or a flat list of containers
space or enterExpand or collapse a project
/Filter by project, service, container name or ID
enter on a containerFollow its logs

Compose projects as one row

The tab opens with each Compose project collapsed into one row that sums CPU, memory, I/O and PIDs across its containers. Expand it to see services and containers. Project memory is a sum only, without a limit or percentage, because containers can share one host limit. If any member's sample is missing, the project shows — rather than a partial total.

Sparklines

The panel under the table shows CPU and memory for the selected container over the last two minutes, with average and peak. Short spikes stay visible when the chart is compressed. History starts when you first open the tab and stays in memory for the session; the panel hides below 80 columns.

How rates are measured

Rates come from the daemon's own timestamps and counter differences between samples, not totals divided by uptime. The first sample of a container, a counter reset, or a gap of more than ten seconds shows — until there is a new baseline. An idle container shows 0B/s.

The Containers tab shows CPU too

You don't need the Stats tab for a quick look: every running container on the Containers tab has a small CPU graph and its memory, from the same stream. Press o and choose CPU graph to switch between a braille graph, bars, a single meter, or off.
