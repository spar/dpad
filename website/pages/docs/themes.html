A theme sets every color dpad draws: tab accents, container states, health badges, usage bars, sparklines, log levels and the selected row. Eleven ship with dpad, and your own is one YAML file.

Pick one

Press C in the TUI, or open settings with o and choose Theme. Moving through the list previews each theme on the whole screen. enter keeps it and saves it to config.yaml; esc goes back to the one you had.

Or set it yourself:

# ~/.config/dpad/config.yaml
theme: matrix
$ dp --theme amber          # one run
$ DPAD_THEME=nord dp ps     # one shell
$ dp themes                 # list them, with swatches

Themes apply to dp ps, dp images, dp stats and dp logs as well as the TUI. The CLI changes text colors only, so your terminal keeps its background.

Write your own

Put a .yaml file in ~/.config/dpad/themes/, next to config.yaml. The file name is the theme's name, so midnight.yaml is chosen with theme: midnight, and it shows up in the picker and in dp themes. A theme only needs the colors it changes; the rest come from the theme it extends, or from default.

# ~/.config/dpad/themes/midnight.yaml
description: Nord, with a darker background and red tabs for production
extends: nord

terminal:
  background: "#1b1f27"

tabs:
  containers: "#d57780"

Quote hex colors, since YAML reads an unquoted # as a comment. To try a file without installing it, pass its path: dp --theme ./midnight.yaml.

The theme file reference lists every color role, and Adding a theme to dpad explains how to contribute one.

Fewer colors, or none

On terminals with 256 or 16 colors, dpad maps each color to the nearest one the terminal has. Output is plain when piped, when NO_COLOR is set, or with --no-color.
