dpad works without a config file. Add one when you want your own commands on a key, or to keep settings such as the theme and editor.

Where it lives

SystemPath
macOS and Linux~/.config/dpad/config.yaml, or $XDG_CONFIG_HOME/dpad/config.yaml when that is set
Windows%AppData%\dpad\config.yaml
Anywherethe path in DPAD_CONFIG

The settings screen (o) shows which file dp is using. dp reads it at startup.

Settings

theme: matrix      # see Themes
editor: nano       # for Compose edits; builtin for the built-in editor
cpuGraph: bars     # braille (default), bars, meter or off
icons: nerd        # auto (default), nerd or off
hostPanel: off     # hide the host panel on the Containers tab
mouse: false       # leave the mouse to the terminal

You rarely need to type these. The theme picker (C) and the settings screen (o) write theme, editor, cpuGraph, hostPanel and icons for you, changing only that line and leaving the rest of the file as you wrote it.

icons puts a Nerd Font logo for the image before each container name, such as the PostgreSQL elephant. auto turns them on in terminals that ship the symbols themselves (Ghostty, WezTerm and kitty 0.36 or later); choose nerd if your terminal font is a Nerd Font.

Custom commands

customCommands:
  - name: top
    key: T
    command: docker top {{.ID}}
  - name: bash
    key: b
    attach: true
    command: docker exec -it {{.ID}} bash
  - name: compose down
    key: O
    scope: project
    confirm: true
    command: docker compose -p {{.Project}} down
FieldMeaning
nameshown in help, confirmations and the status line
keya key dp doesn't already use, such as b, T or ctrl+o
scopecontainer (default): a container row in Containers, Stats, Projects or Events. project: a project row in Projects
commandrun by /bin/sh -c, or PowerShell on Windows
attachtrue hands the terminal to the command, for interactive commands; dp comes back when it exits
confirmtrue asks y/N first

Placeholders

Container commands can use {{.ID}}, {{.Name}}, {{.Image}}, {{.Project}}, {{.Service}} and {{.WorkingDir}} (the Compose project folder). Project commands can use {{.Project}} and {{.WorkingDir}}. Values are inserted already quoted as single words, so don't add quotes around them. Only placeholders are allowed between {{ }}; Go template actions such as {{if}} are not.

How they run

  • Commands talk to the same daemon as the dashboard: dp sets DOCKER_HOST to its endpoint, so they work on an SSH context too.
  • Without attach, a command runs in the background and its last line of output, or its error, appears in the status line. Use attach to read all of it, for example docker logs {{.ID}} | less.
  • Your keys appear in ? help on the tabs they apply to.
  • A problem in the file, such as a key dp already uses, a duplicate key or an unknown placeholder, shows in the status line at startup. The other commands still load.

Compose project variables

composeProjects supplies variables a project's Compose files need when dpad updates it and can't recover them from the containers:

composeProjects:
  my-project:
    env:
      STACK_NAME: production
