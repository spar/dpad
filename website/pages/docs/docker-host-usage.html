docker stats tells you what each container uses, but not how busy the machine is. dpad puts the host next to its containers: how many cores and how much memory it has, how much is in use, and how much of that is Docker.

The host panel

The Containers tab (1) starts with three rows:

RowShows
SystemThe host's name, CPU use across all its cores, and memory in use out of the total
DockerThe Docker version, and the CPU and memory all containers use together
HostThe OS, the load average and the uptime

The gauges turn yellow and red as usage climbs, like the Stats bars. A wide terminal adds network rates, swap, the running count, the kernel and the architecture. Press t to hide the panel and give its rows back to the list; dp remembers the choice as hostPanel: off in the config file.

The System screen

Press I on any tab for everything dp knows about the daemon and its host:

  • Host: name, OS, kernel, architecture, cores and memory, uptime and load.
  • Engine: Docker and API version, runtime, containerd, storage driver, cgroup version and driver, logging driver.
  • Usage: CPU, memory and the disk that holds Docker's data, for the host and its containers.
  • Disk usage: what docker system df reports for images, containers, volumes and build cache, with how much is reclaimable.
  • Warnings the daemon reports, such as missing swap limit support.

Disk usage can take a while on a busy host, so dp reads it when the screen opens and again when you press r.

Where the numbers come from

Names, cores, memory, OS, versions and drivers come from the daemon's /info and /version, read every 30 seconds. The host's own CPU, memory, load, uptime and disk come from its /proc and df, read every two seconds by one long-running shell loop:

  • Local Linux daemon: the loop runs on your machine.
  • Remote daemon over ssh://: the loop runs on the server over one extra SSH connection, so the panel describes the server, not your laptop. Nothing is installed there. See remote Docker over SSH.
  • Docker Desktop and tcp://: Docker runs in a VM, or there is no shell to reach, so the System row says host usage isn't available and the Docker row still shows the containers.

The Docker row adds up the same per-container stats as the CPU graph, so it needs a CPU graph style other than off (o → CPU graph).
